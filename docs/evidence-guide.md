# 源码仓库中的验收与原始证据

Git 仓库保存实现、教材、固定输入和验收说明。作者工作区的 `artifacts/` 包含运行日志、数据库演练产物、冻结源码和候选归档，体积大且可能带有本机路径与环境身份，因此不随源码入库。

## 如何阅读历史记录

`docs/validation*.md`、阶段报告和部分实验中的 `../artifacts/...` 或 `../../artifacts/...` 链接，是作者原工作区的相对证据位置。它们在该工作区可读取，在仅克隆源码的环境中没有对应文件。历史记录保留原链接和源码身份，避免为了网页显示而改写已绑定的验收材料。

| 材料 | 在源码仓库中可取得什么 |
| --- | --- |
| [W26 验收记录](validation-week26.md) | 实际冻结身份、通过数量、失败保留情况、清理结果和待验收项 |
| [结果索引说明](results-index.md) | 原候选证据的布局、检查顺序与历史结果范围 |
| [已知限制](known-limitations.md) | 当前支持能力与尚无实际证据的环境 |
| [实验手册](../labs/L01-state-machine.md)及[命令参考](command-reference.md) | 在自己的环境中重新执行适用实验的方法 |
| 作者工作区的 `artifacts/` 原件 | 需要单独取得的原始日志、报告和归档；首次源码提交不包含这些文件 |

当前 GitHub 首页和入库入口只链接随源码提供的文档。入库检查将历史 `artifacts/` 引用单列为工作区证据引用，不把它们计为源码文件链接通过，也不把它们误判为工具安装缺失。

## 重新运行与取得原件

重新运行按 [README](../README.md)、相应实验手册和[跨环境执行手册](cross-environment-validation.md)执行，使用新的输出目录和独立实验资源。新结果记录自己的平台、源码、命令、退出码与日志；不能将另一个工作区的新结果填回旧候选 manifest。

需要审查作者原始结果时，先约定具体周次、源码 manifest 和需要的文件，再单独交付经过检查的证据集合与校验摘要。未取得原件时只能阅读仓库中的验收说明，不能声称已独立复核其原始证据。正式可下载的证据地址确定后，再增加实际可用的链接。

SHA256 用于核对内容一致性；真人、主机身份和发行许可分别确认。新的复现结果不会自动解除真人试读、冷主机或完整 Linux 隔离的待验收状态。
