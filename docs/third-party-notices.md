# 阅读站的第三方版权与许可证

本项目的原创代码采用 Apache-2.0，原创教材采用 CC BY 4.0；站点使用的第三方软件、字体和图标保留各自的版权与许可。它们不因出现在本项目网页中而被重新许可。

生产阅读站页脚的“第三方版权与许可证”打开与当前构建一起生成的清单。每项列出名称、版本、适用许可、原始许可文件与取得源码的说明；机器可读清单还记录文件摘要。直接下载静态站点产物时，保留整个 `licenses/` 目录。

在已构建的阅读站中：<a href="../licenses/third-party/index.html" target="_self">打开本次构建的第三方版权、许可证与源码取得说明</a>。

## 清单覆盖什么

- VitePress、Vue、MiniSearch、Mermaid 以及实际进入浏览器脚本的转依赖，包括延迟加载的图示代码。
- 上游已预打包、因此不直接显示为当前 npm 模块的代码：根据实际使用文件的 source map 与已核对的补充清单识别。
- VitePress 随附的 Inter 字体及主题图标。字体字节与固定版本的来源摘要核对，随站点保留对应许可。

这些文件供浏览器渲染和检索教材使用；它们与[实验源码包](experiment-package.md)的范围不同。站点不会把本地实验数据、数据库、凭据、原始诊断日志或整个 `node_modules/` 发布出去。

## 取得第三方源码

生成清单记录 npm 包的精确版本、原始压缩包地址与 integrity 摘要。已预打包组件的来源单独列出；建站时的压缩与打包不改变其原始许可。

elkjs 0.9.3 的相关代码按 EPL-2.0 分发；生成产物附带完整许可和 `SOURCE-AVAILABILITY.txt`，说明如何从官方项目取得相应源码及构建说明。预编译包中的 GWT、Guava、EMF GWT 与 Xtext 运行库也单独保留许可和原版权声明，其中 EMF GWT 的源文件适用 EPL-1.0，不能用 elkjs 的 EPL-2.0 代替。清单提供固定版本的上游源码包链接与摘要。其 [0.9.3 发布记录](https://github.com/kieler/elkjs/releases/tag/0.9.3)注明基于 ELK 0.9.1 并包含额外修订，不将它简化成只需取得任意一个 ELK 版本。

## 维护与验证

在完整源码的 `website/` 目录执行 `npm ci`、`npm run check`、`npm run build`。构建从实际客户端模块产生清单，检查安装版本与锁文件；缺少许可、遇到未经审查的预打包依赖或字体变化时停止构建。生成之后还检查许可文件、脚本、字体与清单的摘要。

升级依赖时同时复核原文及补充来源；不能通过填入项目自己的 Apache 许可证来替代缺失的第三方许可。[站点维护说明](reading-site.md)记录完整构建、预览和 Pages 发布流程；线上清单对应实际部署的站点构建。
