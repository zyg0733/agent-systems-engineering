# ADR 0001：纯状态内核与显式副作用

- 状态：已接受
- 日期：2026-10-19
- 适用范围：Agent Systems Lab 第 1—2 周

## 背景

Agent 同时涉及模型响应、工具效果、进程生命周期与任务状态。把它们写在一个循环里，虽然容易得到一次演示成功，却难以判断错误发生在决策、执行还是状态记录阶段。第一阶段需要一个可离线运行、能复现轨迹的教学系统，为后续持久化与恢复实验留下明确边界。

本阶段只研究受控的模型与工具。真实模型、网络工具、任意 Shell 执行、数据库和跨进程调度均不进入这个实现。

## 决策

1. `AgentSystemsLab.Kernel` 是纯状态机。`dispatch/2` 检查命令，返回新状态与有序事件；不调用模型、不发送消息、不执行工具、不读取时钟。
2. 事件描述已接受的业务事实。状态通过 `apply_event/2` 演进，`rebuild` 用同一事件应用逻辑重建内存状态。事件重放不得再次访问 Provider 或工具。
3. `Scripted Provider` 按固定序列返回响应。脚本位置属于 Provider 状态，不能藏在纯内核中。相同初态、命令和脚本得到相同轨迹。
4. `Mock Tool` 使用独立 GenServer，分别记录请求次数与真实效果次数。操作编号是幂等键；相同编号只能对应相同参数，参数冲突必须报错。
5. 工具回执有三类：确认成功、确认失败、结果未知。`unknown` 使任务进入 `blocked`；只有显式查询并核对，才可继续。超时或丢响应不等于业务效果失败。
6. `RunServer` 负责手动驱动执行步骤和保存当前进程状态。OTP 进程重启不自动恢复任务，也不自动重试业务效果。

## 主要不变量

- 终态 `succeeded`、`failed`、`cancelled` 不接受后续业务命令。
- 只有 `running` 能接受模型响应；只有 `waiting_tool` 能接收当前操作的初次结果。
- 一个任务最多有一个待处理操作；结果中的编号必须匹配当前操作。
- 同一任务不能再次申请相同 `operation_id`，即使该操作已经完成。
- `blocked` 必须核对当前未知操作，不能直接接受新的模型响应。
- 事件序号连续递增；模型轮数受到 `max_turns` 限制。
- 非法命令返回错误，不产生事件，也不改变调用者持有的原状态。

## 后果

纯内核可以用普通 ExUnit 测试覆盖合法与非法转换，无须启动整个应用。独立工具台账允许我们证明“请求两次”与“效果一次”的区别。Provider 和工具可替换，内核契约保持稳定。

代价是需要显式传递命令、事件和状态，并在驱动层处理多个步骤。这个额外结构是后续学习 intent/outcome、故障恢复与执行权控制的实验接口。

本阶段的事件列表、Mock 台账与 RunServer 状态都在内存中。`rebuild` 只证明已持有完整事件列表时能重建相同状态，不证明事件已经落盘，也不承诺断电恢复、跨节点恢复或端到端 exactly-once。未来加入存储时必须另写 ADR，定义何时算持久化确认、怎样原子提交、怎样处理工具效果与结果记录之间的空隙。

## 验证

`mix test` 验证状态转换、不变量、脚本响应与 Mock 故障语义；`mix lab.verify` 执行固定任务集并报告结果；L01 要求学生独立构造拒绝命令与丢回执实验，解释观察结果。演示命令只提供操作示例，不替代实验验收。
