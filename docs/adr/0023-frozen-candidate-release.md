# ADR 0023：冻结故障矩阵与可校验教学候选包

状态：W24 实现；实际执行结论见 [W24 验收](../validation-week24.md)。技术候选与正式发行分别记录。源码项目版本保持 `0.1.0-dev`，目标 `0.1.0`，候选标签为 `v0.1.0-rc.1`。当前目录没有 Git 仓库，包标签不表示创建 Git tag，也不执行上传或部署。

## 背景

原计划要求在同一冻结源码上对 12 类故障逐类至少重复 20 次，交付 12 个课程单元、30 张设计卡、六章试读稿、已知限制、结果索引和后续清单。旧 P2/P3、W22 复现与 W23 源码准备有各自的源码和日期，不能合并旧运行次数冒充本周矩阵。真实读者仍为 0，用户已选择先完成试读包与技术验收，P5 外部准入继续待验收。

## 决定

以固定宿主工具完成冻结计划和受控执行。计划是结构化数据；运行器仅执行受版本管理的固定场景，拒绝任意场景、命令、报告输入和降低重复次数。输出本轮源码身份、每个故障点每次执行的结果及原始证据；未完成或任一断言失败均不能生成成功矩阵。真实效果、操作台账、结果配对、旧 claim 拒绝和可见 unknown 分别验证，不以“最终状态成功”替代全部断言。

教学包把源码/文档与本轮证据一起冻结，清楚记录当前/目标/候选三个版本身份及完整性信息。包只包含 allowlist 内的源码材料和有界结果文件，不包含 runtime、deps、build、PGDATA、既有开发库备份、凭据或旧试读反馈。本轮受管新库升级实验的合成 `.dump`、P2 `.bin` 和 `.jsonl` 可作为惰性字节证据；校验不执行、反序列化或导入它们，复制 archive 不携带原主 BEAM capability，也不解除 restore gate。故意的隔离符号链接、无扩展名 native 探针和缓存明确排除，原始实验产物另保留。

验证只处理有界文件、结构化元数据与完整性，不启动业务应用、模型、工具或数据库，不执行报告文字。完整性 hash 用于检查字节一致，不认证来源或真人身份。

技术候选允许如实保留尚未取得的外部准入：`release_ready=false` 与 0 名真人不会被包验证改成通过。W22 原冻结试读包保持协议与字节，当前候选不覆盖它；需要新版本试读时另建协议。Linux CI 配置、同宿主 warm-cache 复现、六章稿和 30 张卡片均按其实际范围标记。

## 源码和结果的边界

先完成源码、测试和静态说明，再冻结执行候选并运行矩阵及全量/内存回归。执行后结果以独立证据文件和包内索引绑定，不把结果补录进原冻结源码。最终派生验收文档留在包外，明确引用执行候选与最终包身份；这样不会循环修改源码 hash 或用后补文档冒充测试时源码。

`ReleaseReadiness` 仍是 W23 源码准备合同，其固定 `week24_matrix=pending` 不读取本周实测证据。本周实际矩阵与包各有独立报告，不能把源码准备工具升级成“自动发布批准器”。

## 不变式与验收

业务状态机、SQL migration、依赖锁、权限、已扣预算、绝对 deadline、原 operation ID、unknown/reconcile、审批 subject/hash/generation、lease/heartbeat/fencing 保持。取消不能撤销已有效果，重建不得执行，恢复不能换 ID 盲重发。新工具不得直接改账本、放大预算、解除 restore gate 或接管未登记资源。

验收包括固定矩阵完整性、场景断言、真实故障的逐轮证据、文件/元数据篡改拒绝、输出边界、包自含性、无业务执行的验证、完整回归与内存回归。没有真实执行的 gate 明确待验收，失败产物保留。操作与教学任务见 [L23](../../labs/L23-frozen-candidate-release.md)、[参考判断](../../labs/solutions/L23.md)、[候选交付说明](../candidate-release.md)和[结果索引](../results-index.md)。
