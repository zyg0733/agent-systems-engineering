# ADR 0016：静态 DAG、预算预留与原 Run 恢复语义

- 状态：接受，用于第 17 周教学实现；真实验收以 validation-week17 为准。
- 日期：2026-10-21。
- 依据：[研究计划](../../Agent%20Systems%20Engineering%20研究与落地计划.md)、[持久化后台调度](0010-background-scheduling.md)、[背压与公平性](0012-backpressure-and-fairness.md)、[MCP](0015-mcp-stdio.md)、[L16](../../labs/L16-dag-workflows.md)。

## 问题

单 Run 的决策和状态转换仍需串行化，但相互独立的小任务可以并行，再以确定的来源关系汇合。新增 DAG 不能绕过原有权限、预算、事件顺序、领取、lease/fencing、调用 ID 或未知效果核对。编排器崩溃与取消还可能发生在依赖释放和工具执行之间，单靠进程内 Task 列表无法恢复正确状态。

## 决定

采用可信宿主定义的静态有向无环图，每图最多八节点，最大反链宽度三，实际并发 `max_parallel` 为一至三。拒绝环、自依赖、缺失或重复节点、重复依赖、未知字段和不安全值。使用字典序稳定的拓扑顺序与哈希生成的稳定子 Run ID；不从模型结果生成节点、宿主选项或图变更。

定义、版本、哈希、工作流绝对 deadline、子节点投影、事件链、私有队列和已就绪子 Run 通过 PostgreSQL 事务保存。后续依赖观察与子 Run 创建也在事务内完成。只读取已经提交的成功来源，不能以 Worker 发送完成消息代替数据库事实。读入口重建并核对定义、历史、投影和子节点身份，不执行模型或工具。

子节点继续作为普通 Recovery Run 执行。Coordinator 只观察和推进依赖，由可替换的、工作流队列范围受限的原 Scheduler 执行。数据库队列限制多个 Coordinator 合计的在途数量；领取、续租、fencing 和原工具回执仍是唯一执行与提交权威。停止 Coordinator 暂停其交付；持久化取消采用独立父图门禁与子任务收敛流程。

每个节点独立保存 Session、文件工作区、隔离和 MCP 策略。已知策略通过各自严格 schema 往返为 inert map；不接受 hook、函数、queue 或直接 permissions 覆盖。不同节点文件授权根不能相同或互为祖先。`:implementer` 与 `:reviewer` 是静态角色，不新增权限；Reviewer 读取依赖 bundle，只能使用自己被批准的工作区和工具。

工作流总预算使用五维静态预留：turn、model attempt、output bytes、tool call 和 delivery dispatch。每一维子节点分配总量不能超过父 cap。重试保留原子 Run 的计数和时间限制，崩溃不退款；未使用额度不动态分配。所有节点共享创建时确定的绝对总 deadline，下游创建不会重置工作流时间。此实现不是动态 credit 池、token 计费或资金预算。

依赖按 ID 排序，以独立来源列表汇合。保留原任务、完整成功输出、Run ID、seq、完整 operation ledger、源哈希与 bundle 哈希；不用共享 map 的覆盖顺序决定结果。inert Erlang 数据用 tagged JSON 无损表达，保留 atom/字符串 key 类型、tuple 与非 UTF-8 binary，不转成权限配置。汇合输入最多一 MiB，超过上限显式失败，不截断来源。

明确失败向父图传播并停止其他未终态子节点，未创建的下游 skipped。取消先提交父状态，再收敛子 Run；已准备或已发送的非幂等工具结果可能是 unknown，因此父图 failed/cancelled 与 blocked 子节点可以同时存在。已有回执优先复用，原核对队列继续可见。人工核对只解决原操作，不重开已终止图，不自动重投模糊结果。

## 验证

纯测试覆盖图结构、最大反链、规范化与严格恢复、静态预算、选项拒绝、独立工作区、策略往返、稳定排序及完整回执哈希。真实 PostgreSQL 测试覆盖依赖、并发领取、多个 Coordinator、失败传播、取消门禁、同一子 Run 恢复及提交前后崩溃。正式演练保存可重复检查的定义、输入、事件和预算事实，另用新 BEAM 核对只读重建相同且效果入口为零。

同预算单 Agent 与“实施者加 Reviewer”对照需让总 cap 和实际分配总量均相同，并使用真正的一条 Run 与两条 Run 完成相同两产物任务和结构化意见。它与相同四节点图在 `max_parallel=1/2` 下的串行/并行调度对照分别留证；Worker 数量不能当成 Agent 数量。固定 Scripted Provider 的结果只说明编排、隔离与预算机制；不将固定脚本对照当作多 Agent 质量优势证据。数量和通过结论仅从实际测试及验收记录填写。

## 后果与后续边界

编排保持有界，并复用已验证的执行权威与恢复语义。代价是保守预留可能闲置额度，私有队列和完整投影增加数据库记录，完整来源也可能触发汇合或 protected context 上限。发生这些情况应留下明确失败及原事实，不能临时删证据或放宽权限。

本周不实现动态 DAG、自动 Planner、自动返工或发布审批。Reviewer 可以返回结构化审查意见，但 `approved` 字段不是人工授权。人工批准、产物哈希绑定与产物变化失效在后续阶段独立实现；Linux 与硬内存/总磁盘配额等既有隔离能力边界也不会因 DAG 而改变。
