# ADR 0008：有限重试、持久退避与可见结果核对

- 状态：已接受
- 日期：2026-10-21
- 范围：第 9 周、L08
- 延续：[ADR 0007](0007-recovery-and-operation-attempts.md)、[ADR 0006](0006-history-checkpoints-and-recorded-results.md)

## 背景

上一阶段已经能领取当前意图、保留预算与游标，并在工具结果不明时停下来核对。还需要回答另一个问题：失败之后何时可以再试、最多试几次，以及应该重试请求还是核对已经可能发生的效果。

把所有错误统一交给无限循环会掩盖权限、schema 和预算错误，也可能重复执行非幂等业务。只在 worker 内 sleep 则会让退避计划随进程退出而丢失。与此同时，blocked 只是 Kernel 状态；操作人还需要一个可查询入口，看见哪些任务卡在结果核对、为什么卡住，以及有哪些原始投递记录。

## 决策

1. 重试是显式、创建时固定的策略。新增策略使用独立持久 sidecar，保留原 Recovery 配置 v1 的精确结构与版本校验。未指定策略的任务继续采用第 8 周行为；不把旧任务隐式升级为会重试的任务，也不在 resume 时扩大原策略。
2. 错误分类区分暂时故障、永久故障、预算/取消等停止条件，以及结果未知。分类保留原因与发生边界；重试资格还必须同时满足策略、当前意图、claim、预算、deadline 与工具能力。字符串中出现 timeout 不能单独构成重试授权。
3. 有限重试使用确定性的封顶指数退避。默认策略为总尝试上限 3 次、初始间隔 100 ms、最大间隔 5000 ms、当前工作的总重试窗口 30 秒、工具超时 1000 ms。总尝试上限包含第一次尝试。实验不加入 jitter，便于精确验证；真实共享服务上的退避拥塞问题不在本阶段解决。
4. 失败尝试、首次开始时间、下一次到期时间、耗尽原因和相关身份持久保存，并绑定原 Run、seq 与工作范围。下一次时间通过数据库时钟决定。退避不会重置 Run 的绝对 deadline、累计模型尝试或已消费输出预算。模型/工具的候选到期时间达到重试窗口或 Run deadline 时，当前策略耗尽，不再启动新执行。只读结果核对使用自己的有限查询窗口，可以在执行 deadline 后查明已经可能发生的效果。
5. 等待退避不占用睡眠中的执行 worker。未到期时返回可观察的暂停快照，释放当前 claim；显式 resume 在到期后重新读取并领取资格。resume 不在一次调用中忙等到期，不提供常驻定时扫描器或后台 daemon。进程重启不能令 due 时间提前，也不能使尝试计数归零。
6. 模型暂时错误和策略允许的模型请求超时可以有限重试。失败请求已经产生的输出开销保留，cursor 仅在完整响应被接受时前进；半截流不成为录制结果。schema 错误、权限错误、Run deadline、输出预算或总尝试预算耗尽，不通过重试获取新的授权或配额。
7. 工具超时按效果语义处理。能够证明尚未产生效果的暂时失败，仍须经过能力契约与有限策略才能再次投递。已经可能产生效果的超时、回执丢失和 worker 失联进入 unknown；非幂等或无法权威查询的工具不能因此自动重发。模型请求可重试的结论不能机械套用到工具业务操作。
8. 重投保留原 operation ID 和精确参数，每次实际投递新增 attempt。幂等能力只解决重复业务效果；它不能代替当前 claim 校验、预算或重试上限。未知结果优先查询原身份的权威回执，查询 attempt 与执行 attempt 可区分；查询未命中也只有在能力契约足够强时才支持后续动作。
9. 新增只读核对队列，从经验证的 blocked Kernel 事实、当前 reconcile 意图与持久工具记录派生。队列不保存第二份可以独立修改的业务状态。list/get 与 CLI 只展示事实，不领取、不调用模型、不执行工具、不自动解除 blocked。取消或成功核对后，任务自然离开当前核对队列，原始 attempts 和证据继续保留。
10. 解除 unknown 仍通过显式 Recovery.reconcile。支持权威查询的工具可以查询原回执；查询的暂时错误和等待超时进入独立 `:reconcile` journal，受同一策略的次数、退避和自身 elapsed 窗口约束，不产生业务效果。无法查明或查询机会耗尽时继续阻塞，不把 unknown 改写为业务失败。人工结果必须绑定当前 Run、operation、expected seq 与非空证据，记录为新的核对事实；人工确认不占用自动查询的重试配额。证据是可信操作人的声明，不是程序自动验证外部世界的凭证；人工确认不会自动撤销已发生效果。
11. 故障注入覆盖暂时错误后的持久退避、到期前进程退出、到期接管、耗尽、超时、迟到结果、工具效果与回执之间的歧义，以及核对事务 COMMIT 前后。验证除了最终 State，还包含尝试计数、due 时间、cursor、预算、业务效果数与队列可见性。原有重建零效果测试和全部前序实验继续运行。

## 三类时间与三类身份

| 事实 | 约束范围 | 跨进程处理 |
| --- | --- | --- |
| Run deadline | 模型/工具新执行的总时间上限 | 恢复时沿用绝对时刻；不阻止核对已有效果 |
| retry window / due | 当前待处理工作可重试多久、下次何时可尝试 | 数据库保存并重新验证 |
| 单次请求/工具超时 | 一次 attempt 的等待上限 | 超时后先判断效果是否已知 |
| operation ID | 一次稳定业务意图与精确参数 | 重投、查询与核对都保留 |
| attempt ID | 一次具体请求、投递或查询 | 每次真实尝试独立留档 |
| claim token | 当前 Runtime 推进资格 | 到期、接管或取消后旧 token 失效 |

这些限制同时生效。较长的 retry window 不会延长 Run deadline；更换 worker 不会重置 attempt 上限；新的 claim token 也不授权更换 operation 身份。

一次尝试在产生效果前提交 reservation。相同 claim token 再次 reserve 被拒绝；新 token 接管遗留的 inflight 请求时，先记录旧尝试的放弃结果。模型或只读查询可以由有限策略安排下一次机会，工具遗留执行则保守进入 unknown 核对，不能因接管而假定尚未产生效果。

## 结果路径

```text
当前意图 + 有效 claim
        │
        ▼
持久记录尝试 ── 调用 Provider / 工具
        │
        ├─ 完整已知结果 ── 校验并事务提交接受事实
        │
        ├─ 可重试暂时故障 ── 校验所有上限
        │                       ├─ 可继续：持久 due，释放 claim，返回暂停
        │                       └─ 耗尽：提交明确失败
        │
        ├─ 永久错误 / 预算 / deadline ── 停止，不重新分配配额
        │
        └─ 可能已有外部效果 ── unknown / blocked / 可见核对队列
                                 │
                                 ├─ 权威回执 ── 显式 reconcile
                                 └─ 无法查明 ── 保留阻塞，等待人工证据
```

退避到期仅意味着可以重新评估，不保证任务必然再次执行。下一位 worker 仍要验证当前历史、claim、预算与能力。人工核对也是新的状态转换，不能直接编辑 projection 绕过历史与版本检查。

## 代价与范围

持久 retry journal 增加状态与事务验证成本。数据库可用性与时钟仍是实验前提；本阶段没有全局调度公平性、生产级拥塞控制、真实 Provider HTTP 重试或跨服务幂等协议。确定性故障脚本用于复现特定尝试，不是模拟厂商对模糊请求的保证。

核对队列是可见性入口，保持只读；需要操作人的任务不会因为出现在队列中就被自动完成。文件系统与 PostgreSQL 仍不共享事务，工具超时也不等于外部取消成功。本决策不承诺任意外部系统的 exactly-once、文件效果回滚或真实模型连接续接。
