# ADR 0004：受控文件工具与调用结果配对

- 状态：已接受
- 日期：2026-10-20
- 适用范围：Agent Systems Lab 第 5 周、L04
- 延续：[ADR 0001](0001-pure-kernel-and-explicit-effects.md)、[ADR 0002](0002-transactional-storage.md)、[ADR 0003](0003-streaming-cancellation-and-budgets.md)

## 背景

Mock 证明了模型提议、效果执行和未知结果需要分开，但没有向真实文件系统施加约束。接入文件工具后，一个通用 Map 不再足以表达输入契约；调用 ID 与返回内容必须配对，否则结果可能记到错误操作上。修复实验还需要原内容版本、补丁的明确前置条件和可审查的 diff。

本周实现离线、手动推进、单待处理调用的工具路径。Runtime 获得明确指定的私人 workspace 后才公开文件能力；不从模型输入、当前目录或工具参数隐式推导授权目录。实验没有模型 shell 工具，也不自动执行任意生成代码。

## 决策

1. 公开工具白名单和字符串键参数 schema。Provider context 增加 `available_tools`，保留已有 `run_id`、`input`、`turn_count` 与 `operations`。未配置 workspace 时只公开兼容的 `mock_write`；有效 workspace 增加 `file_read`、`file_write`、`file_patch`。
2. Runtime 在完整模型响应被接受前校验已知文件工具是否启用、参数类型、必需字段与额外字段。流式 JSON 仍在完整结束后才作为候选调用验证；半截参数不能创建操作。外部 `command/2` 提交模型响应也走相同工具契约，不能绕过 Provider 路径直接建立非法文件意图。未知工具名称保留旧实验的受控错误行为：可以接受调用提议，执行时返回 `unsupported_tool`，不会获得目录之外的执行能力。
3. 继续使用 `operation_id` 标识本 Run 内的 Provider 调用与逻辑操作，接受后不可重复。当前每个操作单 attempt，不引入独立重试尝试身份；Streaming 的请求引用只关联模型进程与消息，不能作为持久调用 ID。
4. 新文件结果使用 `{:ok | :error | :unknown, envelope}`；envelope 精确包含 `type: "tool_result.v1"`、`operation_id`、`tool`、`output`。Kernel 校验外层待处理 ID，并对显式版本封装校验内层 ID、工具名和形状，派发、重建与核对共用规则。当前 RunServer 对文件结果强制要求封装，Gateway 总会添加封装。Kernel 仍允许已有 v1 未带封装的历史，包括过去恰好以 `file_read` 等名字作为未知工具记录的错误结果；不因新 Runtime 契约而破坏旧历史重放。
5. 文件工具状态与去重台账由当前 RunServer 持有，不放进纯 Kernel。相同适配器实例内，相同 ID、工具和参数返回原回执，不重复效果；同 ID 的不同输入得到冲突。台账、统计和 workspace 能力不是持久 checkpoint。
6. 文件读取只读普通文本文件；写入必须提供目标内容及 `expected_sha256`；补丁必须提供版本 hash 和顺序 edit 列表。`"absent"` 只允许新建。旧内容 hash 不符时拒绝覆盖；每个 edit 的非空 `old` 必须唯一匹配，先在内存中预检全部修改，再一次替换目标。
7. 单文件内容和每项 edit 文本受 64 KiB 限额，patch 最多 32 个 edit；只接收合法 UTF-8 且无 NUL 的文本。结果中的 diff 由受限的前后内容派生，大小可超过单份内容限额。路径相对授权 workspace，拒绝绝对路径、dot/dotdot、反斜杠、保留元数据目录与符号链接；普通文件必须只有一个硬链接，父目录必须已经存在。没有 shell、删除、建目录或任意执行工具。
8. 更新通过同目录临时文件、同步和重命名执行。提交前重查已知前置条件，失败清理临时文件；不在参数或部分 edit 成功时直接改写目标。该文件操作不与 PostgreSQL 事务合并。
9. 离线演示通过 Scripted Provider 提议读取缺陷文件、patch、写修复说明、最终回答，生成 `repair.diff` 和验收证据。固定免运费门槛从 `subtotal > 100` 改为 `subtotal >= 100`，修复前 3/4 测试通过，修复后 4/4 通过。宿主核对源文件与测试字节后才执行该受信任 fixture；模型没有通用执行能力。输出目录必须新建，拒绝覆盖旧实验。

## 工具契约

| 工具 | 参数 | 主要执行前置条件 |
| --- | --- | --- |
| `file_read` | `path` | 允许路径，普通 UTF-8 文本文件，无 NUL，大小不超过 64 KiB |
| `file_write` | `path`、`content`、`expected_sha256` | 父目录已存在，内容受限，现有文件 hash 匹配或明确 `"absent"` |
| `file_patch` | `path`、`expected_sha256`、`edits` | 当前 hash 匹配，1—32 项 edit，每项精确为 `old`/`new`，每个 old 非空且唯一匹配 |

上述文件工具的输入键均为字符串，不接受未知字段；旧 Mock 仍允许任意 Map。模型看到的 schema 与服务端实际校验需要一起维护；schema 描述不替代执行时的文件事实检查。schema 拒绝发生在创建工具意图之前；文件变化等执行期错误发生在已接受调用之后，作为带同一调用身份的结果返回。

对文件能力的授权来自 `workspace` 配置，不来自 `expected_sha256`。知道一个外部文件的 hash 不表示能读取或修改它。`file_write` 与 `file_patch` 分开使新建/整体替换和精确局部修改有明确意图，二者均不能删除文件。

## 三层身份与记账

```text
Provider context / schema
         │ 完整工具提议 (operation_id, tool, arguments)
         ▼
Kernel operation ── 单个 pending ID ── 工具执行与本地台账
         ▲                                      │
         └──── outcome + tool_result.v1 envelope ┘
                       ID 与工具名必须配对
```

Kernel 拒绝第二个同 ID 模型提议，执行器台账拒绝同 ID 改输入；前者维护业务历史唯一性，后者限制重复效果。二者的生命周期不同。下轮模型 context 携带已接受 `operations`，其中包含配对结果；不能只有内部记账而不把工具观察返回给模型。

result 的 `output` 是数据，不是待执行代码或可信指令。即使读取内容建议改写另一文件，也必须经下一轮显式调用和同一参数/目录检查。结果封装的版本独立于业务 Event schema 版本，当前没有修改持久 State 的字段形状。写入结果提供修改前后 hash、内容字节数与整个文件单一 hunk 的 unified/Git-compatible diff；新建非空文件使用 `/dev/null`，空文件创建使用 Git 扩展头。

## 文件系统边界

workspace 必须是宿主显式提供的已有绝对目录，面向没有恶意并发写者的私人实验目录。路径分量检查、链接检查、文件类型和 hash 检查用于拒绝确定的越界、危险类型和已知陈旧内容。单纯做字符串前缀比较不足以验证目录边界。

根及相对路径的保留组件和内部临时文件前缀统一按 Unicode casefold 比较，拒绝 `.GIT`、`.awſ`、`depſ` 等别名。macOS 的实际文件系统会把部分大小写或 Unicode 字符视为同一名称，单纯区分大小写的字符串比较会漏掉保护目录。路径还拒绝全部 C0、DEL 控制字符；这项规则同时避免 diff header 的换行和分隔符混淆。

这些检查没有把宿主文件系统变成内核沙箱。目录项可能在检查后变化，hash 读取与最终替换之间仍存在 TOCTOU 窗口；当前没有基于目录句柄的完整隔离、跨进程 lease 或 fencing。需要处理恶意共享目录时，应引入更强隔离与操作原语，不能扩大本实验的适用前提。

全补丁预检保证检查失败时不会落盘前几个 edit。原子重命名减少读者看见半写目标的风险；它不提供跨多个文件的原子性，也不自动证明断电后的目录项耐久性。实验承诺与测试围绕单个文件调用的明确前置条件及结果展开。

## 持久化与崩溃窗口

```text
事务 A：Run + tool_requested + tool 意图
                    │
          文件读取 / 替换（数据库事务外）
                    │
事务 B：Run + 配对结果 Event + 下一项意图
```

Run、Event 与调度意图继续按 ADR 0002 事务提交。文件替换无法参加同一 PostgreSQL 事务，因此事务 A 后崩溃可留下未执行或已执行的工具；文件已替换、事务 B 前崩溃也可能只留下 pending 意图。不能看到 pending 就盲目重发，不能因取消或失败终态推断文件从未变动。

内存台账只在存活适配器中去重，重启后不会恢复。hash 失配可能提示内容已变化，但不能证明是哪次调用造成，也不能重建丢失回执。本周不提供未知文件效果的自动重试或安全自动续跑；后续需要持久操作台账、核对和尝试身份。

文件执行前继续检查 PostgreSQL 中是否已经出现新的状态/序号，拒绝确定陈旧的 owner。数据库读取与文件替换间仍有竞争，因而该检查不是跨系统 fencing。模型取消仍可在流期间及时处理，文件工具为短时同步执行；不承诺任意慢文件系统操作期间的即时抢占。

读取 PostgreSQL 与 Kernel 重建只还原已接受事实，不调用文件适配器。原目录不存在或内容已变化，不影响读取历史中的文件结果。Storage 仅扩展受信任内部词汇的预加载，保持 safe ETF 解码；不为了新工具放宽不可序列化内容规则。

## 验证与后果

测试覆盖能力公开、严格 schema、工具名与调用 ID、结果封装双层配对、路径与链接、内容与大小、hash 冲突、多 edit 全预检、原子写临时文件清理、内存去重和同 ID 改输入。Runtime 回归证明接受后执行前取消无写入、结果进入下轮 Provider context，数据库回归证明配对结果持久化、新 VM 读取、重建无文件效果、陈旧 owner 无写入。原有完整测试与 L02 提交边界检查继续执行。

成本是工具目录、校验与文件适配器增加了需要共同维护的契约；文件内容进入结果历史也会增加持久数据量，因此内容限额不能只放在 Provider 输出预算中。离线修复以 diff、固定前后验收与调用配对给出可审查证据，不把脚本模型的固定输出描述成真实模型的修复能力。

实验步骤与破坏练习见 [L04](../../labs/L04-controlled-tools.md)，测试数量与实际验证命令由第 5 周验收记录保存。
