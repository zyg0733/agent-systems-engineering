# ADR 0024：版本化发行评估与追加式试读闭环

状态：W25 实现；实际运行结论另见本周验收。承接 [ADR 0023](0023-frozen-candidate-release.md)、[下一阶段计划](../next-stage-plan.md)与 [L24](../../labs/L24-versioned-release-assessment.md)。项目版本继续为 `0.1.0-dev`，目标 `0.1.0` 未发布。

## 背景

W24 的 `v0.1.0-rc.1` 已把固定源码、回归、冻结矩阵和教学材料绑定成可校验候选。候选工具刻意固定真实读者为 0、Linux 待验收、正式发行关闭；它的合同与原始证据需要保留。W22 试读工具从工作区导出，原始 blocker 没有追加式解决记录，不能直接承担修订后的发行评估。

技术候选验证、真人反馈、冷主机复现、Linux 完整能力和所有者发行决定是不同事实。新的工具需要将其绑定到同一源码，并拒绝未知版本、错协议、证据漂移和旧反馈挪用；不能把自洽 JSON 当成真人或平台认证。

## 决定

新增独立的 `ReleaseAssessment` 与 `ReleaseStudy`，使用各自版本化的 kind/schema。旧 `CandidatePackage`、`ReaderStudy` 和 `ReleaseReadiness` 的合同不改，W22 原包、W24 rc.1 目录和归档保持原样。新评估产生新的惰性报告，不回写旧 manifest，也不创建 tag、上传或发布。

发行政策在受版本管理的固定合同中声明。W25 保留现有 3—5 名独立真人、六章反馈、至少一次新工作区固定主实验、冷主机复现及完整 Linux 隔离与冻结验收的要求。下一阶段计划提出过 macOS 范围建议，该建议未被采纳为新政策；Linux 的适用子集通过不能替代完整门槛。外部证据缺失时保持 pending。

新试读包必须显式选择已通过 `Reproduction.verify/1` 的纯源码冻结导出，带候选证据的完整包根不能直接作为 source。包内复制的 source manifest 原始字节身份、六章及实验资产和新协议相互绑定。准备过程不从当前工作区默选另一版，不执行冻结源码中的代码；模板、作者、代理和自动测试不计真人。可信 W25 工具和被评估 W24 rc.1 保持两个源码身份；新包根说明接收/评估在可信工具完成，不给旧源码添新 CLI 或修改旧指南来冒充相同身份。

原始反馈保留输入字节并独占保存。问题带稳定 issue ID；解决记录按连续序号与前一记录 hash 追加，并由 head 绑定末尾。一次 fix 只是待复验的修复声明；只有原反馈读者针对最近 fix 的成功 retest 才关闭问题，失败仍保持未解决。报告只读重算，不通过覆盖原反馈或删除 blocker 改绿。

同一 source 下可以记录外部环境或说明问题的修复与复验；修改包内源码或章稿需要重新冻结、新包与新协议。旧反馈和失败继续保留在旧包，不能给新 source 改 hash 后直接继承通过。反馈路径、命令文字和证据 hash 只作数据，不触发任意文件读取、命令执行或网络访问。

## 故障与可信边界

追加操作由独占锁串行化；写入中断、head 不一致、序号缺失、未知事件或链损坏均明确失败。操作者保留现场并调查，不自动删锁、截断尾部或重写 hash 链。普通文件 hash 只能发现相对于已知锚点的漂移；没有外部可信锚点时，不声称可以识别完整的自洽历史重写或回滚。

所有报告都是可信宿主提供材料后的结构和完整性评估。读者 ID、自报独立性、fresh_workspace、环境说明和 hash 不认证自然人或独立机器，不重新证明命令实际执行；人工身份、来源与批准仍由项目所有者核对。缺少外部证据不妨碍本地工具完成，但不解除正式发行门槛。

本周不改变状态机、SQL migration、依赖锁、权限、预算、原绝对 deadline、operation ID、unknown/reconcile、审批产物 hash 或 lease/heartbeat/fencing。报告失败不会推进 Run；文件账本不是业务恢复账本。实现入口、操作和失败处理见[发行评估手册](../release-assessment.md)、[L24](../../labs/L24-versioned-release-assessment.md)及[参考判断](../../labs/solutions/L24.md)。
