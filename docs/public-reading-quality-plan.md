## 2 代理评审如何开展

至少分三种视角，评审者不参与自己所审材料的首轮编辑：

1. 后端工程师、初接触 Elixir：从首页找先修，辨认命令/IEx 边界，走首次小练习，指出解释中隐含的知识。
2. 熟悉 OTP/SQL 的工程师：核对事务、unknown、checkpoint、lease/fencing 和取消语义，提出不成立的情境。
3. Agent 应用开发者：按六章串联模型、状态、效果与恢复，检查是否能用新情境解释，而非只照抄输出。

角色模拟是审查方法，不虚构真实读者、满意度或完成率。记录代理的实际判断、材料位置、问题与修复；代码实跑和浏览器实测单列。代理静态阅读未执行的命令必须标为未执行。当前没有真人学习成绩，也不将它设为本轮完成条件。

## 3 技术核对的重点

首批核对 12 条：拒绝命令不改变事实；final 占模型轮数；纯重建零执行；Context 权威来源；ETF 字节不等于 token；checkpoint hash 不等于签名或执行授权；receipt 不等于 Kernel 接受；COMMIT error 不证明回滚；unknown 不等于可盲重试的失败；lease 不等于旧进程已停止；fencing 必须在持久提交门验证；取消不撤销既有效果或退回已用预算。

每条保留精确源码与测试入口、前提/反例、核查方式、实际执行状态。尤其解释 blocked Run 可以取消：操作中的 unknown 事实不会消失，但原 Run 终态后不能经 reconcile 续跑；可信宿主后续离线核对与 Workflow 父取消的子核对策略分别说明。不为修文案静默改变状态机契约。

可执行例子要写明 shell/IEx 上下文、环境、输出目录和预期断言。纯值、内存、数据库和隔离分别记录；不把旧版本结果直接继承为新稿件执行证明，不自动执行任意 Markdown 围栏。真实 PostgreSQL 集成由适用专项与远程 Lab checks 提供证据，Linux 排除 Seatbelt 的事实保持。

## 4 借鉴成熟公开教材

本轮已研究三个一手项目，具体观察和落地决策见[公开教材借鉴记录](learning-design-references.md)：

- Hugging Face Agents Course：先修、入口分流、小测与完整实践相衔接。
- Microsoft AI Agents for Beginners：按目标选择路线，每章说明学什么与下一步小任务。
- Dive into Deep Learning：概念、可执行代码、结果、小结和修改条件后的练习紧邻。

采用适合本书的组织方法，沿用 VitePress 和现有 Elixir 实验，不照搬外部框架、账号、证书、排行榜或他人正文/图表。

## 5 阅读站与功能优先级

当前优先让读者找到并读懂材料：入口直接链接先修、六章、术语和当前状态；练习先显示问题，提示/参考推理按需展开；代码复制、中文搜索、前后章、最近章节和图示可用。

检查桌面与 320/390 CSS px 窄屏的导航和局部代码/表格滚动；键盘可操作搜索、关闭并返回；关键图旁有文字推理。继续阅读只表示最近章节，不等于学习完成率。代理与浏览器检查可以发现具体问题，但不据此虚称 WCAG 全面一致或真实学习成效。

暂缓登录、积分、评论、证书、笔记平台和真实 Provider 扩展。先把小量正文及现有功能做好，再按代理审查发现扩充章节。

## 6 与历史发行工具的关系

W22/W24/W25/W26 的冻结记录、原协议、候选和版本化 ReleaseAssessment 工具保留原语义，其中 human_readers=0、旧 P5 未通过等字段不伪造为完成。它们是旧实验/候选的历史事实，**不再作为本轮教材编辑和代理评审的真人准入条件**。

本轮报告采用独立的教材修订记录，不向旧真人 JSON schema 填代理身份；不要求先完成旧工具的所有外部 gate 才能继续写书。正式软件版本、Git tag、托管开放与教材修订分别处理，本轮只完成用户授权的私有提交和验证。
