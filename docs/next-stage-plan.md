W25/W26 工具、历史候选、原试读协议和 W24 冻结矩阵保留各自源码身份。旧版 ReleaseAssessment 仍按它的固定政策运行，human_readers=0、原 P5 未通过、release_ready=false 等历史字段不被手改为通过；这些字段不作为本轮教材修订、代理评审或继续写作的真人前置要求。

冷 macOS、完整 Linux 隔离和正式版本发行仍按实际能力分别描述。Linux core 通过不能冒充 Seatbelt 等价隔离，代理也不冒充真人。当前目标是交付经过检查的书稿与阅读站，不创建正式 tag 或发布网站。

## 3 全书草稿的维护方式

每批使用“编辑→不同角色代理模拟→交叉技术核对→修复→实际检查→提交”的循环。只把实际执行的命令、退出码与报告列为运行证据；静态核查、角色模拟、浏览器操作分别记录。没有真实学习耗时，就不给读者编造学习完成率或满意度。

先修和桥接允许精简，但必须足以衔接当前正文，不让读者依赖尚未写出的长章。每批优先处理会导致错误理解、实验误操作和断裂导航的问题，再改善排版。旧失败、旧归档、冻结源码与原始证据保持原样，改动后的正文和实验取得新身份。

日后是否开放教材与源码，按新的明确授权决定；没有真人公开试读这一预设流程。当前私有仓库推送和 Actions 检查已获授权，持续按本轮任务执行。

每章由其他作者交叉技术审查；全书按七篇模拟阅读依赖与迁移问题，明确静态作答、实际运行和未执行部分。原有七章同步补齐顺序阅读衔接，代码片段的执行身份另行核对。站点章节导航和最近阅读共用一份 30 章清单。

## 5 v0.2 可选工程路线

只有教学确实需要且另有工程容量时启动。单一作者启动下面工程任务，就暂停相应周数的新章目标；若希望与教材并行，需要另一名工程负责人。现有候选与教材基线保持可复现，实验改动使用独立工作副本或后续版本线。

首个 v0.2 目标限定为 **一个真实 Provider 的受控调用、持久预算与结果录制恢复**。先完成该闭环，再决定是否增加备份、性能或观测扩展。

| 工程顺序 | 实施内容 | 验收条件 |
| --- | --- | --- |
| V1 第 1 周 | 显式 Provider 装配表、持久配置兼容 | Scripted/Recorded 和一个新适配器共用合同；schema1 历史仍可读；未知 ID/配置拒绝；密钥不持久化，不从报告加载任意模块 |
| V2 第 2 周 | HTTP/Streaming 传输与错误处理 | 本地伪服务验证任意分帧、截断、429/5xx、畸形响应、取消、超时、断连和迟到结果；缓冲/连接/进程有界 |
| V3 第 3 周 | 持久成本预留与结算 | 请求前保守预留；记录价格快照、币种/整数单位与 usage；结算幂等；计费不确定进入可见状态，重试/崩溃不自动退款 |
| V4 第 4 周 | 录制与恢复配置新版本 | 保留旧录制读取；请求前、首帧后、完成后提交前、提交后确认前故障均覆盖；旧 claim 拒绝；纯重建零网络/模型/工具调用 |
| V5 第 5 周 | 小规模真实评测 | 先 5 个任务估算用量；显式配置 Provider/模型/总费用/请求数/时间上限后才启用；保留全部尝试，成功率、真实成本和延迟分开统计 |
| V6 第 6 周 | v0.2 候选冻结 | 原完整回归、相关固定故障矩阵与新网络/计费窗口通过；结果、限制、运行手册、包与解压校验绑定同一源码 |

最小实际改动点包含 `RunServer` 的构造/stream/录制 provider ID，以及 `Recovery` 的严格配置和模型启动；仅新增 behaviour 实现不足以接通。当前 Stream 只支持纯 final 或一个 tool call，第一版继续明确支持这一子集，不静默丢弃多调用或混合内容。

首个网络适配验证 TLS、固定允许的 endpoint，凭据只由可信宿主解析；Provider 网络许可不传递给工具或隔离执行器。真实网络请求可能在供应商已接收、本地未录制时重复产生费用，不能承诺模型请求 exactly-once。usage 缺失或计费模糊时保留未知预留；报告分别列出 usage×版本化价格的估算与可取得的最终账单，缺账单时不称精确实付。网络默认关闭；确定 Provider、模型与预算后使用显式命令启用，普通 CI 继续离线。实现时核对所选供应商的官方协议与当时价格，不在本计划固定会变动的单价。

后续可分别申请三个小专项，不挤进上述六周：

- **跨 BEAM 备份信任，约 2—3 工程周。** 先限定同可信宿主、受认证来源、新自有目标。默认只读→exact proof→旧 claim 换代→显式激活；新签发 capability，不能持久化旧 capability、把 hash 当授权或手改 marker。工作区与外部效果单独核对，不扩展成任意 dump 导入或 PITR。
- **恢复成本基线，约 1—2 工程周。** 在 100/1000/4096 Event 和另行预声明的大历史样本测 SQL 读取量、内存、锁时长、p50/p95、样本数和环境。重建与 checkpoint 状态一致、零外部执行。当前 checkpoint 仍全量校验前缀，先量化，再讨论新的可信前缀协议；不删历史或放宽迁移上限换速度。
- **OTLP，约 1—2 工程周且按需。** 只有确需远程收集时实现；collector 断连、超时、缓冲饱和下业务事实相同，缓冲和进程有界，敏感内容不外泄。优先级低于读者、安装和章节闭环。

## 6 保留完整 Linux 门槛时的平台专项

这条路线需独立 Linux 环境和安全审阅，预留 4—6 个工程周，不与同一作者的一章/周并行承诺。

1. **第 1 周：能力和威胁模型。** 固定可用 runner、用户/内核权限与隔离设施；定义允许的文件、网络、进程和资源合同。不具备所需设施时明确拒绝。
2. **第 2 周：文件与网络隔离。** 最小 Linux executor；越界路径、符号链接、未授权读取/写入、外联与解析路径有负向测试；保留现有 Gateway 权限检查。
3. **第 3 周：进程生命周期和资源。** 验证超时、CPU/输出等声明限额、Worker 被杀及父进程退出后的后代清理；不能因缺少设施静默取消限制。硬内存/总磁盘配额若未实现，继续明确列限制。
4. **第 4 周：恢复与跨平台冻结。** 断连、取消、unknown、旧 claim fencing、审批产物变化均保持；Linux 和 macOS 各保存适用全量回归与固定故障证据。解除 Linux blocker 必须有完整能力证据。
5. **第 5—6 周预留：** 安全审阅、环境差异与失败修复；任何新修订重新生成源码身份及必要验证。

普通容器或 CI 成功本身不计为隔离验收。平台设施的具体选择在获得 runner 约束后确定，避免先承诺当前宿主无法验证的后端。

## 7 所有迭代共同的完成标准

| 准入项 | 必须保留的事实 |
| --- | --- |
| 源码和证据 | 新源码有新身份；版本变更在验收前落定；不修改旧 manifest 消除漂移，不把另一源码的通过数搬来 |
| 权限 | Provider、反馈、MCP 发现和恢复都不能自行提升工具权限；审批继续绑定产物 hash/代次 |
| 预算和时间 | 保留原已用额度与绝对 deadline；重试、崩溃、暂停、维护不退款、不重开期限 |
| 效果和恢复 | 调用/结果配对；未知结果可见核对；纯重建零执行；租约过期后旧执行代次不能提交 |
| 测试 | 原覆盖继续有效，新用例计数照实记录；完整与内存模式、fixture、提交窗口、相关故障矩阵均按范围执行；不放宽原门槛消除失败 |
| 产物 | 测试、实验、解答、ADR/操作手册、实际验收、结果索引、限制和 backlog 同步；没有执行的环境继续 pending |
| 事实范围 | 代理模拟、实际执行、冷主机、Linux 与发行状态分别记录；不把模拟写成真实用户成绩 |

下一次完整冻结仍按 **12 类各 20 轮** 验收，组件探针单列；开发阶段按受影响范围快速测试，不在每次小改动后盲目重复重故障演练。正式新候选完成全量验收，失败目录保留。共享数据库和旧包继续做前后保护，资源只按本轮明确所有权清理。
