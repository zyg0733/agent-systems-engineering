# v0.1 候选之后的工作清单

本清单承接 [W24 候选交付](candidate-release.md)与[已知限制](known-limitations.md)。优先级表示后续投入顺序，不表示已经排定日期、承诺功能或授权发布。当前项目仍为 `0.1.0-dev`，候选包标签为 `v0.1.0-rc.1`；运行时权限、已用预算、原绝对 deadline、unknown、审批与 fencing 不因清单条目改变。

W25 已提供[同源码新试读与版本化发行评估工具](release-assessment.md)，原 W22 包和 rc.1 保留原样。这是 P0 的技术准备：真实读者仍为 0，冷主机与完整 Linux 证据待验收，P0 外部准入尚未完成。继续按原政策收集材料，不采用计划中未经确认的 macOS 降范围建议；实际工具验收见 [W25](validation-week25.md)。

W26 增加[跨环境固定执行与有界证据采集](cross-environment-validation.md)，以及当前源码测试临时目录的平台适配。工具、计划和本机 warm-cache 验收不关闭外部条目；新主机冷安装、真实 Linux 核心执行、完整 Linux 后端与真人分别按实际证据验收。旧 rc.1 源码不随测试适配改变，详见 [W26](validation-week26.md)。

W26 技术验收已完成：冻结源码完整回归 1093 项、内存回归 628 项及 Python 专项 36 项通过。本轮接续[GitHub 本地入库准备](github-onboarding.md)，整理首页、检查脚本和可留存日志的 CI；本地 Git 已初始化。原创代码采用 Apache-2.0、教材采用 CC BY 4.0，见[许可范围说明](licensing.md)；目标仓库仍待确定，真实远程运行结果另记。

每项扩展都先保留基线，再生成新的源码身份、测试和实验结果。修订教案不自动授权发布；性能回归、失败重跑、未执行环境和未收集人类证据均在[结果索引](results-index.md)中分开记录，不靠重设预算或降低门槛消除问题。

新试读的问题关闭继续要求原读者针对最近 fix 成功复验；同源码只闭环包外环境/解释修复，改变代码或章稿后生成新 source/protocol 并取得适用新证据。原始反馈与失败记录保留，锁/半写/断链故障先保全现场。后续若需要账本灾难修复、远程多人协作、身份认证或不可变审计存储，应另立需求与可信锚点合同；本地 hash 链不承担完整自洽重写认证，不能靠改 head 把 P0 变成通过。
