# L25 参考判断

本实验的关键是准确区分已执行事实、文件一致性与外部门槛。固定命令和日志让复现可核对，hash 把报告绑定到具体字节；它们不认证机器、人或安装发布者，也不重新证明历史命令实际执行。

可信 W26 工具与被测 rc.1 是两个源码身份。rc.1 对应 W24 的 502 个冻结源文件；W25 新试读包的 `project/` 也保留这版，因此不含 W26 CLI。宿主在独立工作副本执行旧固定命令，从工具工作区采集证据，不能给旧 project 添脚本后继续声称是原源码。工作副本执行前后要核对 manifest 声明的文件、内容和模式。

同一台机器的新目录、新 PGDATA、新编译，只能证明相应资源没有复用；只要宿主或安装缓存复用，就不是新主机冷安装。冷安装应记录真实新 macOS 主机、缓存状态、五项安装输入来源和工具身份。没有下载发生时不填下载成功；输入 SHA 不能替代签名或可信分发渠道。

Linux 核心模式实际运行适用回归与固定主实验，同时保留 Seatbelt 的排除和隔离后端明确拒绝事实。核心通过不关闭完整 Linux gate；完整 gate 仍需无平台排除、18 项隔离事实和 F01—F12 各 20 轮。不能只改报告 platform、删除 excluded tags 或拿 macOS Seatbelt 输出充当 Linux 后端。

执行授权来自宿主选择的固定计划。证据中的 argv 是数据，不是任意命令入口；未知命令、字段和 schema、源码错配、路径逃逸、链接、超限或已声明文件缺失应拒绝。缺少尚未执行的环境是 pending，已提交损坏材料是 error；二者不能通过默认 true 混为通过。

命令失败、超时和中断都必须保留原退出码、日志与清理结果。先核对独占资源身份，再精确停止本轮 PostgreSQL 并确认端口释放；不停止共享 55432，不按库名前缀批量删除，不因为集群“看起来相似”就接管旧数据。资源归属不明应保存现场，不能自动清理。

测试可构造明确标注 synthetic 的冷主机/Linux 材料来验证合同，但不得放进真实外部证据。当前机器只支持本机 macOS warm-cache 实测；没有实际外部宿主、Linux runner 或真人就继续待验收。完整新源码回归也不能改写旧候选原有测试数或来源。

最终提交应包含本轮冻结工具源码、执行计划、来源声明、原始日志、采集报告、评估结果和旧材料保护记录。外部材料缺失时技术实现仍可交付，正式 `release_ready=false` 保持；发行批准和发布另行处理。实验不重置已有 Run 的权限、预算、deadline、unknown、审批或 fencing。实际操作见[跨环境手册](../../docs/cross-environment-validation.md)，实测见 [W26 验收](../../docs/validation-week26.md)。
