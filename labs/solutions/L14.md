# L14 参考解答

对应 [隔离执行实验](../L14-isolated-execution.md)。实际运行次数、结果和平台以 [第 15 周验收记录](../../docs/validation-week15.md) 为准。

## 1. 为什么路径校验还需要操作系统隔离

文件工具入口可以校验路径，但任意程序可以直接 open、connect 或 fork。固定 cwd、字符串前缀和 worktree 不约束这些系统调用。合格证据必须让程序绕过网关直接调用系统 API：外部 canary 确实存在，open 因 EPERM/EACCES 被拒，外部文件哈希没有改变。ENOENT 只说明找不到文件，不能证明权限策略生效。

workspace 内的符号链接同样需要检查真实目标。只拒绝参数中的 `..` 无法阻止链接越界。

硬链接是另一类权限别名：同一 inode 进入可写 workspace 后，路径边界会改变实际可用权限。启动前要有界检查多链接普通文件，运行时拒绝创建 file-link，并实际尝试将已登记命令链接进 workspace。预检仍要求可信宿主不并发替换根目录与命令，不能声称消除了任意宿主 TOCTOU。

## 2. 怎样证明网络被阻断

使用本次自己创建的 live loopback 服务，并先由未隔离固定探针连接成功，确认地址、端口与监听器有效。随后在相同服务上调用沙箱探针，得到权限拒绝且没有新增成功连接。ECONNREFUSED、DNS 失败、监听器提前关闭或应用层直接拒绝参数，都不构成内核网络隔离证据。无需访问真实外部网站。

## 3. 为什么默认拒绝 fork

只使用进程组 kill 时，能 fork 的恶意程序可能调用 setsid 脱离原组。当前后端通过默认拒绝 process-fork，将目标限定为一个程序，创建后代的尝试必须在内核边界被拒绝。受控原生监督器与目标仍构成需要实际清理的进程树。

RLIMIT_NPROC 按用户计数，不能写成单个沙箱的独立进程配额。允许任意后代的模式需要更强的容器/cgroup 或经过独立验证的归属追踪；本期不开放。

## 4. 各类超限分别证明什么

CPU 硬限制证明计算时间受限，单文件限制证明一个文件不能超过给定大小；二者不等于总内存、总磁盘或全系统资源限额。wall-clock 可以收回睡眠或阻塞目标，输出上限必须停止持续产出，不能仅截断返回日志后放任程序运行。每类实验需命中对应机制，并保留真正退出与清理证据。

取消和调用者崩溃测试必须先确认目标已经启动，再注入停止条件。仅收到 BEAM DOWN 或返回 timeout 不足以证明宿主进程退出；应同时确认本次拥有的目标与监督器结束。

## 5. 为什么初始化错误不能退回宿主执行

后端缺失、策略校验失败或 sandbox 初始化失败都意味着权限边界尚未建立。普通 System.cmd 后备路径会把错误转化为权限扩大。合格实现返回明确错误，并证明原命令没有执行；平台和未支持能力应写入报告。

当前实际验证为 macOS Seatbelt；原计划 Linux 容器首发已明确调整。本机手册将 sandbox-exec 标记 deprecated，Linux namespace/cgroup、跨平台和多租户隔离仍需各自实现与验证，不能由本机结果推导。

## 6. 进程清理为何不能替代业务核对

停止目标不会撤销此前写入的文件，也不能证明此前发送的外部请求没有生效。原 operation ID、receipt、unknown/reconcile、预算与 fenced 提交继续有效。将超时一律写成“没有执行”并自动重发非幂等动作，应判为恢复不变量失败。
