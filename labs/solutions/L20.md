# L20 参考解答：版本、事实与接管必须分别证明

## 为什么不直接提升 Codec 或业务 schema

本周只改变 Event 存储字节的封装，原事件语义和受限 Codec 没有变化。独立 `history_format` 把 layout v1/v2 与 Kernel/Event schema v1、Codec v1 分开，读取先检查格式和 metadata，再解包、校验原字节并 decode。遇到未知域或版本明确拒绝；自动“先按 v2 解，不行就按 v1”会掩盖损坏和新旧结构冲突。

v2 envelope 中的 SHA-256 证明原字节没有意外变化，不证明 archive 来源可信。迁移 journal 绑定源/目标字节、语义 hash 和迁移前缀；合法的新 Event 追加不应使前缀 provenance 失效。

## 为什么旧 fixture 要在新 OS BEAM 中运行

新 schema 写完后把版本列改小不能证明旧 DDL 真能升级。本实验先应用前 20 个 migration，再加载冻结的四个旧存储模块生成没有格式列的新数据库，之后由当前模块升级。四个文件的 hash 必须与第 20 周冻结快照对应；主 BEAM 不替换模块，防止测试后残留旧 Ecto schema。其余业务模块仍是当前实现，因此这是一份精确声明范围的存储兼容 fixture，不是整套旧发行版镜像。

## 迁移是否允许顺便续跑或重算模型

不允许。迁移是受 Run 锁保护的存储事务，expected seq 防止过时计划提交，活跃 claim 拒绝迁移。先读取验证完整 snapshot，再封装原 Event 字节、写 journal，比较结果 snapshot 相同。Provider/工具边界调用计数应为零；工具效果、预算、权限和绝对 deadline 保留。提交前崩溃整笔回滚；提交后重试验证 `already_current`，不能生成第二次效果。

## 还原命令成功是否就能开 Scheduler

不能。先验证受管新目标的全列行、schema、约束、序列和 migration 指纹与静止源相同，再通过 raw Event/checkpoint 重建核对状态。源侧 public readers 校验模型录制、工具配对、Context、预算、Workflow 和审批；目标保持默认只读，不能因业务接口含 `FOR SHARE` 就先解除 gate 运行恢复。

复制的 claim 是旧源的投递凭据。显式激活事务撤销 pending claims 并递增 generation 后，旧 token 必须失效，新 Worker 通过原领取流程获得新代次。预算不退款、deadline 不延长、unknown 不自动成功、旧审批不跳过产物检查。全量原始 hash 在 fence 前相同；fence 后只允许预先声明的 claim 字段变化，受保护事实和 Run 语义仍相同。

旧 DDL 还原路径不应为了 migration 解除整个 staging gate。固定子 BEAM 的专用 Repo 会话升级 DDL 与历史，其他会话保持默认只读；拿到 verified proof 后重新 dump 到第四个新目标，再通过统一 `RestoreGuard` 核验与激活。四个 owned DB/三份 bundle 的矩阵避免把“为升级允许专用会话写入”混同于“允许业务 Worker 使用旧 claim”。

## 为什么 hash 与 read-only gate 都不是安全认证

还原可以执行 archive 提供的 SQL，攻击者同样可以为恶意 dump 计算正确 hash。本接口只接受可信宿主当前主 BEAM registry 生成的 Bundle capability，不接受任意路径导入；磁盘文件是证据，不是授权。数据库默认只读防误操作，有数据库 owner/superuser 权限的人可以改变会话设置，不是恶意用户隔离。

句柄 capability、随机数据库名和数据库 owner marker 共同限制创建/清理范围；仅凭前缀 `lab_w21_` 不足以删除数据库。cleanup 不使用 `DROP ... FORCE`，有连接就拒绝。原生 guardian 必须终止实际 owned OS PID，测试用 PID 消失证明 timeout 与 owner-death 清理，不能以 `Port.close` 或函数返回错误代替。

## 数据库备份没有包括什么

Archive 不含 roles、tablespaces、WAL 或工作区文件，不提供时间点恢复。成功文件工具的回执仅在原授权根与原文件仍存在且 hash 符合时有效；把数据库还原到别处不能创造外部文件或重设许可。本实验保留原工作区，明确验证 completed 不重复写、pending 幂等最多一个效果、非幂等 unknown 继续人工核对、预算耗尽仍失败以及审批 subject 重验。

## 审阅清单

合格交付要同时给出真实旧 DDL 证据、迁移前后语义对照、提交前后故障窗口、未知历史明确拒绝、真实 native dump/restore、只读目标 exact proof、旧 claim fencing 与安全续跑，以及精确 owned DB 清理结果。失败案例保留自己的 manifest/log；报告不泄露密码、token、模型正文或私有 receipt。测试与正式演练的实际数量以 [验收记录](../../docs/validation-week21.md) 为准。
