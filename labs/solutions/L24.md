# L24 参考判断

W25 的完成标准是发行评估、冻结试读和问题闭环可以正确处理材料，不是凭空取得真人、冷机器或 Linux 的外部证据。旧 `v0.1.0-rc.1` 与 W22 原包保留原身份和判断；新评估不能把旧 `release_ready=false` 字段改绿。当前项目仍为 `0.1.0-dev`，包 label 不是 Git tag。

冻结源码身份使用 source manifest 的原始字节 SHA，并同时核验被声明的文件集合、大小、内容和模式。只改 manifest hash 无法使错误源码成为原冻结版本。试读协议还绑定六章和实验资产；协议版本、源码版本和发行政策版本分别校验，未知版本应拒绝。

W25 工具和被评估 W24 rc.1 不必是同一源码：工具在可信 W25 工作区处理文件，试读 `project/` 则保留与候选相同的旧冻结源码。source 输入须为纯源码导出，不能直接使用带候选证据的包根。复制后的旧源码不含新 CLI，根说明必须把接收/评估操作导回可信工具，不能改旧文件再继续声称身份未变。

3—5 个合法反馈 JSON 只满足自报结构条件。读者必须声明为独立外部真人，覆盖固定六章；至少一次新工作区主实验需要六个固定 command ID 的记录。自动模板、fixture、作者和代理不计真人。`fresh_workspace` 不是新主机冷安装，Linux 排除 Seatbelt 后的测试也不是完整 Linux 隔离通过。

原始反馈是事实记录，不能为了通过 gate 删除 blocker。fix 必须引用存在的问题和本轮 source/protocol；fix 本身不关闭问题。只有原读者针对最近 fix 的成功 retest 才关闭；他人的确认、旧 fix 的成功或失败 retest 都不能冒充当前通过。已经关闭的问题仍有原反馈与修复、复验链。

同一 source 可以修正宿主安装环境或另附操作说明，再由读者复验。包内章稿、代码或安装文件发生修改，就产生另一源码身份，需要新协议与新的适用验证；不能在旧包写“修好了”后复用旧读者通过。跨版本修订关系可以在人工记录中解释，不能自动继承成新 gate 已满足。

序号、previous hash、事件 hash 与 head 一起用于发现断链、缺尾和漂移。独占写锁防止并发追加互相覆盖；进程在写入中断后留下的锁或不一致现场应 fail closed。不要直接删锁、覆盖 head 或重写记录使校验通过。没有外部保存的可信 head，文件 hash 链不提供不可抵赖性，也不能识别所有自洽回滚。

发行评估应区分材料完整、发行批准记录和实际发布。结构合法的 pending 是有效评估结果；未知政策、错 source/protocol、未声明字段、缺必需文件或 hash 漂移属于错误，不能补默认 true。外部材料真实存在、真人身份和来源仍由可信宿主核对；JSON 不代替审核或批准。

外部完整测试数与 doctest 数要匹配候选已绑定覆盖，不能只让 full/memory 两份小日志互相相等。工具版本与安装输入按固定政策检查，缺项仍待验收。Linux 隔离要有一致的后端、状态和全部既有探针，不能复用 Seatbelt 报告改一处 platform；原硬内存/总磁盘等 non-goals 继续允许，任意新增 unsupported 能力不接受。

所有新入口处理有界惰性数据，不启动业务应用、连接 PostgreSQL、运行模型/工具、执行反馈中的命令或读取任意证据路径。Mix 编译仍可能写可信工作目录的 `_build`。本地专项可以用临时合成记录覆盖正向路径，但实际交付继续保留真实人数 0、冷主机与 Linux 待验收，并明确注明 fixture 不是真人证据。

最终提交包含新的冻结源码、协议、原始反馈目录、追加账本、评估输入/输出、实际测试和旧材料前后保护记录。本周实测单独写验收文档；不修改执行时冻结源码或旧候选。业务权限、已用预算、绝对 deadline、unknown 核对、审批产物绑定与旧 claim fencing 不受发行材料影响。操作详见[发行评估手册](../../docs/release-assessment.md)与[ADR 0024](../../docs/adr/0024-versioned-release-assessment.md)。
