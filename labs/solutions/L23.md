# L23 参考判断

`lab.freeze plan` 是 inert 固定计划；`run --output ABS` 会实际执行应用、PostgreSQL、工具与故障；`verify --output ABS` 只校验已保存的 schema/hash。计划和校验成功都不能单独证明故障已经发生，仍需本轮逐轮证据、源码身份、退出结果和具体断言。

原路线十二类故障固定为 F01—F12，每类 20 次，合计 240 个行级 observation。P2 16 窗口、fencing 多探针、DB 连接窗口等另报实际子计数；旧周次数与本轮不合并。某一行未完或断言失败，即使其他子窗口数量远超 240，也不能称完整冻结矩阵通过。F07 每轮 100 个相同 ID 请求，100 次请求不是 100 个不同轮次。

COMMIT 前 kill 后没有半笔 Run/Event/intent；提交后丢通知靠周期扫描发现，不能暗中手动 wake 再宣称通知可丢。claim 后崩溃要等待旧 lease 确实失效。效果成功丢响应后按原 operation ID 幂等查询/核对；不可查询、非幂等工具留可见 unknown，不凭重启或超时推断失败。已录制结果由新应用继续消费，不重复已确认工具。

真实 SIGSTOP/SIGCONT 验证旧执行代次即使恢复也不能提交，状态、回执和后续业务 API 均受 fencing。相同 ID 同参数应关联唯一逻辑结果；改参数必须冲突。有限重试不退款、不热循环；绝对 deadline 不因 pause/restart 重置。审批后真实改变产物使旧授权失效，获批 hash 之外的字节不能 release。

受控数据库连接断开/ACK 丢失不同于主机断电、PG 介质损坏或 HA 切换。20 次说明此配置受控窗口的实际结果，不构成任意外部 exactly-once 或生产 SLA。F12 逐轮验证支持事件重建及未知 Event schema/history layout/Codec/兼容版本的拒绝；旧布局实际迁移另看升级实验。不能改 schema 列号或删除历史来兼容。

完整 check 的 tests/doctests、fixture、数据库窗口与内存排除分别记录，不照抄前周数。每次源码改动都重新说明身份；修复后保留失败记录。评测真实 latency regression 继续按原阈值保存，语义/成本 gate 不能替它把比较报告改成 passed。旧 P1/P2/P3/W22 证据注明日期与范围，不变成本周新跑。

`lab.candidate build` 与 `verify` 不执行证据文字、不启动业务应用，也不创建 Git tag、tar 或发布服务。包根就是项目，source manifest、候选 manifest、`START-HERE.md` 和 `candidate-evidence/index.json` 必须自含相对入口；排除 runtime、deps、build、PGDATA、既有开发库备份、凭据和旧反馈。本轮受管合成升级库的 `.dump`、P2 `.bin` 和 `.jsonl` 仅按惰性字节校验，不执行、反序列化或导入；archive 不携带原主 BEAM capability，不能直接成为可信 restore 输入。故意的隔离符号链接、无扩展名 native 探针和缓存明确排除，原始实验产物保留。hash 检测一致性，不认证来源或真人。应在新解压目录检查文件集合与包验证，归档 `.sha256` 不能替代内部校验。

项目 `0.1.0-dev`、目标 `0.1.0`、候选 label `v0.1.0-rc.1`、业务 schema 和报告 schema 是不同身份。本目录没有 Git，`local_manifest_label_not_git_tag` 如实表明候选标签形式。技术候选通过仍保留 `release_ready=false`、0 名真实读者和 Linux 待验收；作者、代理、fixture、自动化不能补足 3–5 人。正式发行与出版各需自己的 gate。

最终验收文档在执行后派生，冻结源码中的说明可以保留执行前状态；机器结果从绑定的包内索引读取。不要把后补结果塞回旧 manifest，也不覆盖 W22 试读包。回收仅凭本轮资源身份，恢复继续遵守原权限、预算、deadline、unknown、审批和 fencing。更多边界见[候选说明](../../docs/candidate-release.md)、[限制](../../docs/known-limitations.md)、[结果索引](../../docs/results-index.md)与[backlog](../../docs/backlog.md)。
